# Roadmap implementation: consumer trust

The [current readiness evidence](2026-09-05-readiness.md) supersedes historical dependency versions and compatibility results below. This document preserves the original review checkpoint and remaining roadmap.

This follows the [remediation roadmap](2026-09-05-remediation-and-roadmap.md). The existing working tree and its 840-test baseline were preserved. The backlog was evaluated as a set of proposals: work here addresses observable failures, executable consumer evidence, and misleading documentation. No packages were published or deployed.

## Validation contract

`pnpm check` remains the required build, source-type, lint, formatting, test, policy, and catalog gate. `pnpm test:package` now also exercises command previews/exit codes, all scaffold kinds, generated tests, combined rules, and consumer APIs in an isolated install of all 21 tarballs. It does not release anything.

Verified locally on Windows with Node 24.15.0: `pnpm check` passed **897 tests in 156 files** and validated all 21 packages, 104 rules, and 38 checks. `pnpm test:package` passed **23 tests in 5 files**, checked 25 public entrypoints, and recorded three intentional skips: Knip, jscpd, and the unconfigured CSS build probe in the minimal consumer's core suite. Generated frontend linting asserts that all four files were scanned. The two known upstream declaration exceptions below were reported by the consumer gate; no additional allowance was introduced.

Write plans reject invalid UTF-8 inputs and unpaired Unicode surrogates in output rather than silently changing bytes during text conversion. This keeps recorded input hashes and generated output content consistent with the files written.

The DOM acceptance fixture pins Lit 3.3.3, XState 5.32.6, and jsdom 26.1.0. The Node 22 declaration baseline rejected Happy DOM 20.14.0's dependency on an unavailable stream type, so that dependency was not adopted. The existing narrowly located Vite Plus/Effect declaration allowances remain unchanged; unexpected declaration errors still fail. Only the actually executed local environment is reported as verified, independent of the configured CI matrix.

## Follow-up priorities

The next substantial investments need real consumer inputs: machine-readable coverage contracts across the whole catalog, tool-version compatibility matrices, compiler-backed type evidence, rendered theme/App Bridge/LCP acceptance, deployment entry graphs, and durable write recovery. These are retained as explicit backlog items. Adding new generic rules, schemas, public packages, or runtime frameworks without a recurring defect and representative fixture would increase maintenance before supplying the missing evidence.

Newly recognized policy syntax and stricter input handling are recorded as consumer-visible minor changes, with migration examples in each changed package README and a changeset. oio retains its draft status.
