Reviewed the best-practice, content and limitation sections of all 47 component documents linked from the [App Home component index](https://shopify.dev/docs/api/app-home/latest/web-components). ## Where additional automation belongs

Shopify's component types already describe supported properties, values and event payloads. Duplicating every property union in lint would create a second API schema that drifts between releases. Native HTML naming, focus attributes, ARIA and image presence belong in upstream `jsx-a11y`, scoped to actual native elements. These mechanisms still require a correctly typed build and the relevant accessibility rules to be enabled.

The reviewed guidance also covers action priority and tone, merchant-oriented wording, errors and recovery, immediate switch persistence, avoiding repeated banners, keyboard alternatives for visual color selection, responsive tables, spacing and grouping, appropriate imagery, text truncation, nonessential tooltip content, task flow and modal interruptions. Those decisions depend on merchant context and rendered behavior. Semantic review prompts can ask for evidence; they cannot turn a passing AST check into an accessibility or usability certification. Suggested item counts, nesting depths and sentence lengths remain contextual recommendations rather than universal lint limits.

Server-side validation and runtime tests remain necessary for file size, currency precision, date restrictions, URL/email validation, retries, cancellation, progress completion, password-manager compatibility and persistence. Component properties such as `required`, `accept` and `maxLength` do not establish these guarantees.

## Source inconsistencies resolved conservatively

The [Page reference](https://shopify.dev/docs/api/app-home/latest/web-components/layout-and-structure/page) restricts breadcrumbs to links in its slot definition but also mentions buttons in its limitations. The rule therefore does not ban breadcrumb buttons. The [Select reference](https://shopify.dev/docs/api/app-home/latest/web-components/forms/select) describes element content in its option slot while its limitations describe plain text; no blanket markup prohibition was added. The [Drop zone reference](https://shopify.dev/docs/api/app-home/latest/web-components/forms/drop-zone) mentions restrictions through `accept`, but its limitations establish that file size validation belongs in application handlers.

The [Image](https://shopify.dev/docs/api/app-home/latest/web-components/media-and-visuals/image) and [Thumbnail](https://shopify.dev/docs/api/app-home/latest/web-components/media-and-visuals/thumbnail) copy recommendations include English image prefixes. These are unsuitable as a universal localized-string lint contract and can conflict with redundant-alt checks designed for native images. Decoration versus information and descriptive accuracy remain review decisions.

## Verification

An independent conformance review also inspected Shopify CLI revision `614187e5204ca6c4bc3c8418b8c6fcb224ab5dae` and its MIT license. The app configuration documentation's abbreviated discovery description was insufficient to reproduce actual CLI selection. The pinned [configuration selector](https://github.com/Shopify/cli/blob/614187e5204ca6c4bc3c8418b8c6fcb224ab5dae/packages/app/src/cli/models/project/config-selection.ts) establishes immediate manifest matching, an `extensions/*` fallback and support for alternate `*.extension.toml` names. The pinned [loader](https://github.com/Shopify/cli/blob/614187e5204ca6c4bc3c8418b8c6fcb224ab5dae/packages/app/src/cli/models/app/loader.ts) establishes entry overrides of root extension defaults. Both behaviors were independently implemented. Nine regression tests failed before the discovery/version fixes; the corrected checks and their affected category, localization and budget tests then passed 66 tests across five files. Unrelated settings no longer activate Function or checkout contracts.

App manifest discovery was also aligned with the pinned CLI's [project filename contract](https://github.com/Shopify/cli/blob/614187e5204ca6c4bc3c8418b8c6fcb224ab5dae/packages/app/src/cli/models/project/project.ts). Backup-style names are ignored during discovery and rejected when explicitly selected. Ordinary named deployments such as `shopify.app.production.toml`, including hyphenated or underscored suffixes, remain valid. Three additional tests reproduced the old filename mismatch; the corrected discovery and affected deployment checks passed 70 focused tests across five files.

The package's integration tests execute the built plugin through the real oxlint CLI. Positive and negative fixtures cover literals, JSX expressions, fragments, inline object spreads, later overrides, unrelated elements, component boundaries, translated labels, shadowed fetch/require calls, GraphQL, Storefront/Ajax paths and deceptive external hostnames. Package build, TypeScript and focused rule tests passed; the root validation gate and packed-consumer checks are recorded in the overall implementation evidence.
