# Shopify structural conformance research — September 5, 2026

Official App Store and Built for Shopify requirement pages were read in full, including category sections. The implementation below captures repository contracts without treating them as Shopify approval. Guidance was independently restated and implemented; no source examples or documentation were copied into the package.

Target and schema provenance was cross-checked against [segment action configuration](https://shopify.dev/docs/apps/build/marketing/customer-segments/build-an-action-extension), [Flow trigger configuration](https://shopify.dev/docs/apps/build/flow/triggers/create), [print action targets](https://shopify.dev/docs/api/admin-extensions/latest/target-apis/core-apis/print-action-extension-api), [Customer Account extension capabilities](https://shopify.dev/docs/api/customer-account-ui-extensions/latest/configuration), and [theme app extension configuration](https://shopify.dev/docs/apps/build/online-store/theme-app-extensions/configuration).

The API version schedule includes grace periods after the nominal one-year support window. A clock-derived rule declaring every older version unsupported would make false claims. Callers instead set reviewed bounds and update them against the official schedule. Experimental query subscriptions in the app configuration examples are outside the webhook/versioned-extension check.

App Store 5.2.5 requires payment apps to be standalone. No global `embedded = true` rule was added. Scope necessity depends on actual functionality and partner approvals, so a list of scope strings cannot prove least privilege. Conditional pixel requirements need declared feature applicability and runtime event verification. App eligibility, merchant counts, account standing, listing accuracy, and most workflow requirements remain external or runtime evidence.

Regression coverage includes malformed TOML, invalid URL encodings and credentials, cloud delivery forms, topic placement, custom directory discovery, deployment isolation, API bound validation, wrong targets, inactive Liquid schema examples, unsupported category inputs, missing document entries, App Bridge ordering, and budget overrides that would weaken the limit.

Two explicit runtime helpers supplement these checks. `evaluateShopifyIframeProtection` evaluates a supplied response using the exact tenant/admin policy described in [iframe protection](https://shopify.dev/docs/apps/build/security/set-up-iframe-protection). Tests reject report-only headers, duplicate directives or origins, wildcards, unrelated tenants, and non-ASCII separators; standalone protection remains a recommendation. `probeShopifyWebhookHmac` uses an injected isolated handler and fixture secret to require a successful signed control plus HTTP 401 for missing, malformed, and body-mismatched signatures. The [delivery verification source](https://shopify.dev/docs/apps/build/webhooks/verify-deliveries) establishes raw-byte HMAC verification. Tests expose handlers that always reject, always accept, check only header presence, or throw. Neither helper makes network requests or proves route coverage, side-effect safety, or real deployment behavior.

`listing-inputs` adds explicit listing metadata and file checks from the [listing best-practices page](https://shopify.dev/docs/apps/launch/shopify-app-store/best-practices): text lengths, icon and image dimensions, desktop screenshot count, and nonempty alt text. It detects exact duplicate file bytes as a limited implementation of App Store 4.4.5. The PNG/JPEG reader independently implements header layout from the [PNG specification](https://www.w3.org/TR/png-3/) and [JPEG specification](https://www.w3.org/Graphics/JPEG/itu-t81.pdf). It reports dimensions encoded in metadata; it does not claim decoding, perceptual uniqueness, or semantic review. Tests include metadata-only positive fixtures specifically to make this limit visible, malformed and truncated headers, a JPEG frame beyond a large application segment, Unicode counting, missing or escaping paths, and copied bytes under different filenames. No runtime dependency was added.
