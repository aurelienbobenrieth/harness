# Loop

For each element the task touches:

1. **Intent.** One line: what the merchant learns here and does next.
2. **Lookup.** Search the project's `catalog.md`, then [catalog.md](../catalog.md), for the intent. Read only that entry in `catalog/<family>.md`, the neighbour its `Not when` names, and the entry's lines in `components.md`. No entry: research it with [method](method.md) and write it with [entry](entry.md).
3. **Ask before any code,** in one round. When several entries fit, offer them in the merchant's words, the recommended one first. Then ask what the chosen entry's `Ask` line leaves open, each with the admin's default. Skip what the request, the code, the catalog or an owner decision answers. Listing "decisions to confirm" after the build is a failure.
4. **Get the admin's values.** The entry is marked `[sheet]` and the sheet is under 30 days old: use it, do not open the admin. No sheet, a stale one, or a state the sheet lacks: measure the admin and write the sheet ([sheets](sheets.md), [reach the admin](method.md#reach-the-admin)). If the browser call fails or a login page shows, do not build that element: quote the failed call and stop there. "Unavailable" without a failed call is false. An entry listed in `sheets/_none.json` as `not reached` has never been measured: measure it now.
5. **Build** with the first rung of the project's build ladder that works. Default ladder: the component `components.md` names for the entry; the UI kit's own component (`recipes/<kit>.md` when the skill has one for the kit: search it for the entry id); a new shared component; custom CSS. A reused component's gaps are yours: fix, in the component, each one the sheet reports on this screen. A gap stays only for a feature the app lacks, a size the kit cannot produce, or a recorded owner decision.
6. **Compare** each state the sheet holds until 0 differences are left. `project.md` gives the app's one command when it has one. Otherwise: `node scripts/compare.cjs <sheet> --expr ours [--ours <map>]` prints an expression; evaluate it in the app's frame with the session's browser tool; save what it returns; `node scripts/compare.cjs <sheet> <result.json> [--ours <map>]`. The parts are found through the map `ours/<entry id>.json`, which needs no change to the app's markup, or through `data-part="<name>"` on the element in code you own. `NOT FOUND on ours` is a missing part or a wrong locator: settle which. Then click every control once and walk each `flow.*` the screen takes part in, from its trigger to the state after.
7. **Write back, in the same pass,** even when the task limits you to front-end files: the map and the steps to reach each state, the entry's lines in `components.md` (path, then `iso` or each gap as the compare prints it, with its reason), any new entry or sheet, and any text of an entry the sheet contradicts. Only an explicit owner ban suspends it; the proposed text then goes in the report.
8. **Report** as below.
