Add `@aurelienbbn/oxlint-plugin-tanstack-query`, a private draft oxlint plugin for TanStack Query v5 failure modes that `@tanstack/eslint-plugin-query` does not cover. Detection is import-gated and alias-aware: hooks, `queryOptions`, `mutationOptions` and `QueryClient` are resolved through imports from `@tanstack/*-query` packages, and option-name rules only run in files that import one. Rules: `no-swallowed-query-fn-error` (catch or `.catch()` in a `queryFn`/`mutationFn` that never rethrows), `require-fetch-status-check-in-query-fn` (global `fetch` without a `response.ok`/`status` check or throw), `no-query-cache-mutation` (in-place mutation in `setQueryData`/`setQueriesData` updaters, `select`, and `getQueryData` results), `require-optimistic-update-guards` (`onMutate` cache writes without `cancelQueries`, or without `onError`/`onSettled`), `no-query-data-in-use-state` (`useState(data)` from non-suspense queries), `query-fn-returns-value` (syntactic stand-in for the type-aware official `no-void-query-fn`, which is inert under oxlint), and two opt-in rules: `no-query-data-sync-effect` (effects copying query data into state) and `test-query-client-hygiene` (shared or retrying `QueryClient` in test files). No autofixes.
